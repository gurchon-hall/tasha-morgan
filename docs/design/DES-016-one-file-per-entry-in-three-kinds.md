# DES-016 - One file per entry, in three kinds

- Context: open questions and design decisions lived in two files plus
  an archive, capped at 25 entries (DES-006). The files mixed rules
  ambiguities, engine gaps and audit bugs under one numbering, and a
  reader of an id in the code had to work out where its entry lived.
- Decision: every entry is its own file, in one of three kinds with their
  own numbering from 001: `RUL` (`docs/rulings/`, how a rule or card text
  is read), `ENG` (`docs/engine/`, an engine mechanism, gap or engine
  bug) and `DES` (`docs/design/`, project choices). File name
  `<ID>-<slug>.md`; front matter `status` (`open` / `resolved` /
  `superseded` + `superseded_by`), `date`, `cards`; title
  `# <ID> - <title>`. Ids are never reused or renumbered. No cap, no
  archive. Each folder's `README.md` index is generated by
  `scripts/docs_index.py`. A resolved RUL/ENG entry is trimmed to
  exactly Situation / Rules & interactions / Solution, as before.
- Consequence: code cites `RUL-nnn` / `ENG-nnn` / `DES-nnn`, and the
  prefix says which folder to open. `UnresolvedRulingError` and
  `blocked_reason` carry a `RUL-` or `ENG-` id. The former ids were
  rewritten everywhere in the repository; no mapping is kept.
